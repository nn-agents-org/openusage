## 2. Контекст и назначение
Данный репозиторий является форком проекта OpenUsage. Поскольку upstream-репозиторий активно развивается и его внутренняя архитектура может претерпевать существенные изменения между версиями, прямое слияние (`git rebase` / `git merge`) в будущем может приводить к тяжелым конфликтам. 

Настоящий документ является **Change Request (CR) спецификацией**, описывающей бизнес-логику, контракты и технические требования к доработкам форка. В случае выхода мажорных обновлений апстрима данная спецификация позволяет заново воспроизвести и внедрить функциональность поверх обновленной кодовой базы.

---

## 3. Обзор изменений
Форк добавляет три ключевые группы возможностей, отсутствующие в upstream:
1. **Динамическая цветовая индикация иконок агентов в строке меню** в зависимости от оставшейся квоты.
2. **Двухрядный макет строки меню** для отображения значений метрик и соответствующих им таймеров сброса (для 5-часового и недельного лимитов) с компактным форматированием (`4d`, `18h`, `45m`).
3. **Корректная обработка простоя (idle) и окончания 5-часовых сессий** для провайдеров Claude, Codex, Antigravity и OpenCode: если сессия не начата или завершилась и израсходовано $0\%$ лимита, таймер сессии скрывается, не зависая в ложном состоянии «скоро сброс» (`soon`) и не подменяясь таймером недельного лимита.

## 4. Спецификация требований

### Требование 1: Цветовая индикация иконок агентов в строке меню
- **Проблема:** В оригинале иконки провайдеров в меню-баре отображаются монохромным черным цветом (template mode). Понять статус квоты без чтения текста невозможно.
- **Бизнес-логика:**
  - Иконка провайдера окрашивается в зависимости от **наибольшего процента использования** среди всех закрепленных в меню-баре метрик данного провайдера (`max(used%)`):
    - **Зеленый (`NSColor.systemGreen`):** Остаток квоты $> 75\%$ (т.е. использовано $< 25\%$).
    - **Синий (`NSColor.systemBlue`):** Стандартный рабочий диапазон ($25\% \le \text{used} < 75\%$).
    - **Желтый (`NSColor.systemYellow` / `Theme.severityColor(.warning)`):** Предупреждение ($75\% \le \text{used} \le 90\%$).
    - **Красный (`NSColor.systemRed`):** Критический уровень ($\text{used} > 90\%$).
    - **Вторичный (`Color.secondary`):** Если у провайдера нет процентных метрик.
- **Точка интеграции:** `MenuBarStripRenderer.swift`, функция `iconColor(for: MenuBarContent.Group)`.

---

### Требование 2: Двухрядный макет строки меню (Метрики + Таймеры сброса)
- **Проблема:** В upstream таймеры в меню-баре отсутствовали либо показывались одной строкой посередине, из-за чего недельный таймер (например, 108ч) подменял сессионный таймер при неактивной сессии.
- **Бизнес-логика:**
  - **Если закреплена 1 метрика:** значение отображается крупно (12pt bold), а таймер сброса (при наличии) — рядом шрифтом 9pt semibold.
  - **Если закреплено 2 метрики (например, 5-часовая сессия и недельный лимит):**
    - **Левая колонка (`metricsView`):** вертикальный стек `VStack(alignment: .trailing, spacing: -2)`:
      - Строка 1: значение метрики 1 (например, расход 5h сессии: `0%`).
      - Строка 2: значение метрики 2 (например, расход недельного лимита: `15%`).
    - **Правая колонка (`resetView`):** вертикальный стек `VStack(alignment: .leading, spacing: -2)`:
      - Строка 1: время до сброса метрики 1 (5h сессия). Если сессия в idle/не начата — строка пустая (невидимый плейсхолдер с сохранением высоты строки).
      - Строка 2: время до сброса метрики 2 (недельный лимит, например `4d`).
    - Если ни у одной метрики провайдера нет таймера сброса, правая колонка не занимает места.
- **Точка интеграции:** `MenuBarStripRenderer.swift` (`resetView`, `MenuBarTextStrip`).

---

### Требование 3: Компактный формат времени сброса (`Formatters.menuBarReset`)
- **Проблема:** Место в строке меню macOS крайне ограничено; полные строки вида "4d 12h" или "108h" загромождают панель.
- **Правила форматирования:**
  - $\ge 24$ часов ($\ge 1$ дня): число полных дней с буквой `d` (например, `4d`, `1d`). Часы и минуты опускаются.
  - $< 24$ часов и $\ge 1$ часа: число полных часов с буквой `h` (например, `23h`, `5h`, `1h`). Минуты опускаются.
  - $< 1$ часа: число минут с буквой `m` (например, `45m`, `1m`).
  - $\le 0$ секунд: возвращается `nil` (либо `"soon"` на уровне виджета при активной истекшей сессии).
- **Точка интеграции:** `Formatters.swift`, метод `static func menuBarReset(_ seconds: TimeInterval) -> String?`.

---

### Требование 4: Определение неначавшейся / завершенной 5-часовой сессии (Idle-режим)
- **Проблема:** 
  1. Пятичасовое окно у большинства провайдеров запускается первым запросом и длится 5 часов. По окончании 5 часов провайдер переходит в idle-режим и ожидает следующей команды для открытия нового окна.
  2. В upstream при $0\%$ расхода или после истечения 5 часов виджеты зависали в состоянии `"soon"` («скоро сброс»), крутили таймер вхолостую или брали таймер от недельного лимита.
- **Специфика провайдеров и правила реализации:**
  - **Общее правило:** Для сессионных окон, если потрачено $0\%$ лимита (`used <= 0`), окно должно считаться не начавшимся (`isFreshSessionWindow == true`), а таймер сброса сессии **не должен показываться** ни в Dashboard, ни в строке меню.
  - **Claude:** 
    - API Anthropic в idle возвращает `five_hour.resets_at = null`. 
    - Использует сигнал `sessionStartSignal = .missingResetDate`.
    - В `menuBarResetText` добавлена проверка `!isFreshSessionWindow(now: now)` — строка меню больше не перехватывает таймер от `Weekly`.
  - **Codex (ChatGPT):**
    - API OpenAI не обнуляет дату сброса при idle и всегда возвращает `reset_after_seconds` / `reset_at`.
    - Для дескрипторов `session` и `spark` явно установлен `sessionStartSignal = .zeroUsage`. При $0\%$ расхода таймер скрывается.
  - **Antigravity (Google Code Assist):**
    - API Google всегда возвращает `resetTime`, даже при `remainingFraction = 1.0` (0% расхода).
    - В `WidgetData.isFreshSessionWindow` для кейса `.zeroUsage` убрано ошибочное ограничение `now < resetsAt`. При `used <= 0` окно считается fresh независимо от того, в будущем или в прошлом находится `resetTime`.
  - **OpenCode:**
    - В `OpenCodeUsageMapper` добавлено условие: если `used == 0` и дата сброса уже наступила (`reportedReset <= capturedAt`), поле `resetsAt` сбрасывается в `nil`, переводя окно в состояние неначавшегося.
- **Точки интеграции:**
  - `WidgetData.swift`: методы `menuBarResetText()` и `isFreshSessionWindow()`.
  - `AccountProviderRuntime+Descriptors.swift`: дескрипторы Codex.
  - `OpenCodeUsageMapper.swift`: метод `window(...)`.
